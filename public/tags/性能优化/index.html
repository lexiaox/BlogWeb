性能优化

从朴素实现到 45 倍加速：一次 x86 单精度 GEMM 优化记录

这个项目在研究什么 我这次关注的是一个高性能计算里非常经典的问题： 单精度矩阵乘法（GEMM）在 x86_64 架构下，怎样一步步从朴素实现优化到高性能实现。 这个问题有代表性，因为 GEMM 不只是一个算法题，它几乎把这些主题全串起来了： 存储层次结构 cache 局部性 指令级并行 SIMD 向量化 寄存器分块 换句话说，这不是单纯“把代码改快一点”，而是在理解硬件之后，让算法更贴近硬件。 为什么朴素 GEMM 会慢 朴素矩阵乘法通常会写成三层循环。 问题不在于它“不会算”，而在于它的访存方式对 cache 很不友好。 尤其是在行主序存储下，如果按常见的 i-j-k 顺序写，矩阵 B 的访问会出现大跨度跳跃： 空间局部性差 CPU 预取不容易生效 cache miss 和 TLB miss 都会增加 所以很多时候，程序慢并不是算力不够，而是内存访问模式已经把性能卡死了。 我的优化路径 这次我按三层思路推进： 先改访问模式 再改缓存复用 最后改指令级并行 1. 循环重排 我先把循环顺序从常见的 i-j-k 调整到更适合行主序访问的顺序。 这么做的目标很明确： 让对 B 和 C 的访问更连续 提升空间局部性 这是最先见效的一步，因为它直接改善了数据访问模式。 2. 缓存分块 仅靠循环重排还不够。 矩阵规模一大，工作集超出 L1/L2 cache 后，性能还是会掉下来。 所以第二步我引入了 blocking / tiling： 把大矩阵切成子块 让参与计算的子块尽量驻留在 cache 中 尽可能重复利用已经加载的数据 这一层本质上是在提高时间局部性。 ...
